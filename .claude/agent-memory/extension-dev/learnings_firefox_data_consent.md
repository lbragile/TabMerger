Implemented Firefox's `browser.permissions.request({ data_collection: [...] })` runtime consent flow (coordinator follow-up to the initial data_collection_permissions manifest declaration — see `learnings_firefox_beta_manifest.md`).

- **Category schema correction**: `technicalAndInteraction` is real and correctly optional-only, but I'd initially declared `websiteContent` — wrong, since nothing in this codebase transmits page content off-device. The right category for "tab URLs leave the browser" (sync uploads, og-preview fetch) is `browsingActivity`, not `websiteContent`. Get this from a fetched primary source per-project, not assumed from category names that sound plausible.
- **Optional categories are NOT granted by default** — this is the whole point of `permissions.request()`. A previous draft of the manifest-only declaration implicitly assumed declaring a category was enough; it isn't, Firefox still requires the runtime request/grant round-trip (except `technicalAndInteraction`, which Firefox shows as an install-time checkbox instead of a runtime prompt, but is still not implicitly granted — check it reads back granted before sending anything).
- **User-activation timing**: `permissions.request()` must be the first `await` in a click/submit handler, with nothing else awaited before it. In an async function, everything before the first `await` runs synchronously in the same call stack as the triggering event, so `e.preventDefault(); if (!(await requestDataConsent(...))) return; setLoading(true); ...` is safe — the call to `requestDataConsent` itself (not just the function containing it) must be the first awaited expression.
- **`Boolean(import.meta.env.FIREFOX)` is wrong for tests**: real WXT builds inject a real boolean, but `vi.stubEnv()` only ever assigns strings, and `Boolean('false')` is `true`. Wrote `isFirefoxBuild()` as `flag === true || flag === 'true'` to handle both.
- **`vi.clearAllMocks()` does NOT reset `mockResolvedValue`/`mockImplementation`** — only clears call history. Several new gating tests that did `mockFoo.mockResolvedValue(false)` in one `it` silently poisoned every later test in the same file that relied on the hoisted default (`true`) and only used `clearAllMocks()` in `beforeEach`. Fix: explicitly re-assert the default resolved value in `beforeEach` for every mock a test might override (`mockCanUploadOnFirefox.mockResolvedValue(true)`, `mockRequestDataConsent.mockResolvedValue(true)`, etc.) — don't rely on hoisted-definition defaults surviving across tests.
- **A `vi.mock(path, factory)`'s inline `vi.fn()` members (not extracted to a hoisted named mock) are NOT reset by `vi.resetModules()` either** — `background.test.ts`'s `supabase.auth.setSession: vi.fn()` (defined directly inside the mock factory, not via `vi.hoisted`) accumulated call counts across every test in the file that used the same literal token args, breaking a `.not.toHaveBeenCalled()` assertion two tests after an unrelated test had legitimately called it. Fix: `vi.mocked(supabase.auth.setSession).mockClear()` immediately before acting, when asserting non-calls on a factory-inline mock.
- **Fully-replacing `vi.mock('@tabmerger/shared', () => ({...}))` in an existing test file breaks silently** when the module under test starts importing a new named export from `@tabmerger/shared` — `syncEngine.test.ts`'s existing full-replacement mock didn't include `SYNC_DATA_CONSENT_CATEGORIES`, so `pushPendingChanges` received `undefined` and crashed on `.length`. Grep every `vi.mock('@tabmerger/shared'` (and any other fully-replaced module) for new imports before adding them to source files that already have test coverage — `importOriginal`-based partial mocks don't have this problem, full-replacement ones do.
- **Design pattern used across all upload sites** (`syncEngine.ts` push, `useSessions.ts`'s `pushSessionToSupabase`, `deviceSessions.ts`'s `doPush`): a single `canUploadOnFirefox()` helper in `syncEngine.ts`, re-exported and imported by the other two — avoids duplicating the `hasDataConsent(SYNC_DATA_CONSENT_CATEGORIES)` check three times and keeps the "what counts as an upload" definition in one place.
- **`uiStore`'s selector-mock pattern** (`vi.mock('@/stores/uiStore', () => ({ useUIStore: (sel) => sel({ openModal: mockOpenModal }) }))`) silently returns `undefined` for any store field the mock object doesn't include — adding a new `syncPausedReason` selector read to `Settings.tsx` didn't need that test file's mock updated at all, since `undefined` is falsy and the new UI branch just doesn't render. Convenient, but means these selector-mocks can mask a real wiring bug (selecting the wrong field) just as easily as they no-op safely for an unrelated field.
