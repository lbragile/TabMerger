Adding a locale (done for `it`):
- Catalog: `src/locales/<lng>/` copying pt-BR's files + `index.ts`; register in `src/locales/index.ts`.
- Plural forms come from `Intl.PluralRules(lng)` (validateCatalog). Italian, like pt-BR/es/fr, needs `_one`, `_many`, `_other`; `_many` (millions) can repeat `_other`. A node one-off that inserts `<base>_many` after every `<base>_other` that has a `<base>_one` sibling works.
- Russian (`ru`) needs `_one`/`_few`/`_many`/`_other` on every plural key. `_other` is the fractional form (1.5): it takes the genitive singular, like `_few` for nouns ("1,5 вкладки"), not a copy of `_many`.
- Shared: `SUPPORTED_LOCALES` + `LOCALE_NATIVE_NAMES` in `packages/shared/src/constants/locales.ts`. Web: `OG_LOCALES` (`web/i18n/locales.ts`) and `CATALOGS` (`web/i18n/messages.ts`).
- Tests that hard-code the list and must be updated: extension `websiteLink.test.ts` (uses an unshipped code as a negative example, pick one still unshipped), `Header/LanguageMenu.test.tsx` and `Modal/Settings.test.tsx` (ordered native-name arrays); web `LanguageSwitcher.test.tsx` and `MobileNavToggle.test.tsx` (`toHaveLength(N)`). `web/__tests__/i18n-negotiate.test.ts` keeps its own local list and needs no change.
- Also `lib/i18n.test.ts` uses an unshipped code (`resolveLocale(...)` falls back to `en`); it used `ko` until Korean shipped, now `tr`.
- Korean (`ko`), like ja/zh-CN, has only `_other`: drop every `_one`. Counters follow the noun ("탭 {{count}}개"). Labels quoted in web `messages/ko/beta.json` were swapped to the catalog wording with a script that also re-picks the particle (을/를, 이/가, 은/는, 와/과, 으로/로) from the last syllable's final consonant; labels ending in "…" or followed by "(" need a manual particle check.
- Tour copy quotes UI labels: reuse the exact translated label strings; demo data names ("Tour demo", "Reading", "Sample: books", "temp group", "Tour practice tab", typed words like `sample`, `group:tour`) stay in English because they're literal data.
- Batch of five (`tr`, `id`, `pl`, `vi`, `hi`, done together): Turkish and Hindi, like English, need only `_one`/`_other` — no extra forms. Indonesian and Vietnamese, like ja/ko/zh-CN, need only `_other` (drop every `_one`). Polish needs the full `_one`/`_few`/`_many`/`_other` set like Russian; its `_other` (fractional, e.g. 1.5) also takes the same form as `_few`/the plural-looking form, not a copy of `_many` — confirmed against `catalogs.test.ts`'s own Polish fixture (`validateCatalog`'s test block hardcodes a Polish example and is the fastest way to double check a new Slavic locale's required suffix set before writing 28 files).
- `src/locales/index.ts` documents each locale's plural-form family in a comment at the top of the file — update that comment line in the same change whenever a locale with a new/shared plural pattern is added, or it silently goes stale.
- Registering 5 locales at once in `src/locales/index.ts` is just 3 edits: the import block, the `TranslatedCatalog` doc comment, and the `catalogs` object — alphabetical-ish ordering matching the existing file's convention (not insertion order) avoids merge noise.
- The two "unshipped locale" test sentinels (`websiteLink.test.ts`'s `it.each` negative-example array, `i18n.test.ts`'s `resolveLocale` fallback assertion) need updating together whenever a sentinel locale ships — switched from `'tr'` to `'ar'` (still unshipped) in this batch. Grep for the old sentinel code across `__tests__/` before assuming you found every occurrence; both lived in `src/__tests__/unit/lib/`.
- `LanguageMenu.test.tsx` and `Settings.test.tsx` both hardcode the *same* ordered native-name array (one for a menu's `menuitemradio`s, one for a `<select>`'s `option`s) — the order follows `SUPPORTED_LOCALES` array order in `packages/shared/src/constants/locales.ts`, not alphabetical and not insertion order into that array, so when `tr/id/pl/vi/hi` were inserted mid-array (after `ko`, before `ja`) in `SUPPORTED_LOCALES`, the test arrays needed the five new names inserted at that same mid-array position, not appended at the end.
- Verified empirically: `tr` catalog created by a prior (opus) run had already produced correct en-matching line counts and `_one`/`_other` parity on all 28 files — the catalog test suite's `validateCatalog` check alone (`vitest run`) is sufficient proof of parity; no need to manually diff keys file-by-file once tsc + the catalogs test both pass.
- `pnpm --filter @tabmerger/extension test -- run` (not `test --run`): the `--` is required so pnpm forwards `run` as a vitest CLI arg instead of swallowing it; confirmed this is the correct invocation for a full non-coverage unit run from a Windows shell in this repo.
- Persian (`fa`), like English, needs only `_one`/`_other`. Digits: extension `{{count}}` interpolation prints Latin digits (i18next does no number formatting here), while web ICU `#` and `{count}` print locale digits (Persian ۰-۹). So tour/beta copy that quotes a rendered extension label with a number ("Remove 1 duplicate") keeps the Latin digit to match the button, while plain web copy can use Persian digits.
- RTL copy (fa/ar/he): the popup, its arrow keys and Chrome's tab strip mirror, so copy that names a physical side or arrow key is mirrored in translation (tour "list on the left" becomes right, "top right" becomes top left, `keyboardMove.howItem` Left becomes Right, `background.menu.scopeLeft`/`scopeRight` swap sides). `dnd.instructions` "Left and Right switch between windows and groups" keeps its meaning. `→` in copy becomes `←`; `>` in "Settings > Data" can stay because it is a bidi-mirrored character.
