- To start a scene exactly where the previous one ends, the recorder replays the previous scene's actions quickly with `setPace` (no grabber), parks the pointer at the previous scene's idle spot, and only then starts the grabber. Frame 1 then equals the previous scene's last frame (verified by rendering both stills).
- Ctrl-click on a saved tab row now opens the popup's selection mode (checkboxes on every row, a bottom bar "N tabs selected / Move to group / Delete", header toggle highlighted). The selection survives a drag and stays on the moved tabs in the destination; leave it with `getByLabel("Cancel selection")` or the next scene starts with the bar showing. The multi-drag ghost reads "+1" for two items.
- A pointer drag held about 600ms over a sidebar group row springs that group open and swaps the main view to it, even though the drop still lands correctly. Keep the hold over the row around 120ms when the story needs the view to stay on the source group.
- `getCdpMouse` and `naturalMouseMove` in `lib/actions.ts` are exported so tour recorders can write their own drag sequences (the existing actions hard-code which group/tab they use); pace (`dragTravel`) still applies.
- To fade a previous scene's drawn elements out inside the next scene without redrawing them, render the previous scene at its last frame in a negative-`from` Sequence, clip it with `clip-path: inset(...)` to the area that holds only those elements, and give it a z-index below the popup so the popup can move over it.
- Tab rows are found by their grip aria-label (`[aria-label^="Drag to reorder tab: Dropbox"]`), which carries the tab title, so a recorder can address a tab by title regardless of order.
- Notes (tab, window, group) all render only as a small muted note icon after saving; the text is only in the editor (the icon's tooltip says just "Edit note"), so a scene that must show saved content draws its own cue. Tab note: right-click row, "Add note", textarea (placeholder "Add a note…"), Save button or Ctrl+Enter. Window rename: double-click the title span; window "More options" also has Rename and Add note.
- Any pointer glide from a window header down to blank space crosses saved-tab rows and flashes the row hover (underline, highlight, red remove button). Leave the pointer where it is, or flick (about 50ms) to blank space.
- Clicking Save collapses the note editor under the pointer, which hovers the row below (fading remove button). Move the pointer away in the same tick as the click, with no post-click wait.
- Search overlay: backdrop click or Ctrl+K closes it but leaves the query in the header search field; only selecting a result (or Enter on one) clears it. Selecting a result just switches the active group (no tab highlight, nothing opens in the browser). Matching is by substring across all groups, each result carrying its group badge.
- Restoring a saved group: the group context menu item "Open all in new window" opens every tab in ONE window; the window menu (More window options) item "Open in browser" opens one real window per saved window and leaves the saved group untouched. Opening is not affected by the saved-copies/close fixes of 2026-10-09 (those change removal, copy and close rules). The Now Open badge flickers (3/11, 3/13, 3/12, then 4/13) while each new window blank first tab is removed. Poll chrome.windows.getAll from a second extension page on the grabber clock to time drawn windows to real ones.
- Sharing is only reachable signed in: header Settings menu then Sign in, then a mandatory "Set up encryption" passphrase dialog; selection mode (Select items), tick the group checkbox ("Select <group name>"), selection bar Share, toast "Link copied to clipboard" (no dialog, the link text never shows). In the sign-in modal scope email and password fields to the dialog: getByLabel(/email/i) otherwise matches a tab row whose title contains the word email. Signing in only changes the header top-right (avatar initials, undo/redo icon state); groups and counts are unchanged. Wait for sync toasts to clear before recording. Deleting the throwaway auth user cascades its shared_bundles rows.
- Two-device sync on the local stack: a plain second profile (temp dir, same unpacked extension so the same extension id, not demo mode) starts with no groups, and its groups, window names and tab notes arrive immediately after sign-in plus passphrase unlock. A change on device A is only pushed at A popup next 30 s sync poll (not on edit), so propagation to B is anywhere from about 1 s to 30+ s (9 s in one probe): do not build a live beat on it. Starring a group reorders the sidebar and moves A active view to whichever group now sits at the old index. Pass the extension storageState theme seed to launchPersistentContext through a spread (`...{ storageState }`) to satisfy the type. Two simultaneous captureScreenshot grabbers (one per browser process) ran fine in one Node process.
