- **Every indexable page builds its metadata with `pageMetadata({ path, title, description })`** (`lib/seo.ts`). Next merges segment metadata shallowly: a page's `openGraph`/`twitter` replaces the root's whole, and a page without them shares as the root layout (og:title, og:url = homepage on every page). Only `title`/`description` fall through to og/twitter automatically (`postProcessMetadata` fills them when the og object lacks them); `url` never does.
- **A page-level `openGraph` drops the `app/opengraph-image.png` file image.** In `resolve-metadata.js`, `mergeStaticMetadata` adds file-convention images only for the segment that owns the file, and only if that segment's `openGraph` has no `images` key; a deeper page's `openGraph` then overwrites it. So the helper names `/opengraph-image.png` and `/twitter-image.png` (served without the `?hash` too) with width/height/alt; a test pins the alt to the `.alt.txt` files. Reading `node_modules/next/dist/lib/metadata/resolve-metadata.js` answers merge questions faster than docs.
- **Title template + brand:** titles must not contain "TabMerger" (the `%s | TabMerger` template adds it; changelog/privacy/terms once rendered it twice). The homepage uses `title: { absolute }`. og/twitter titles get the full string from the helper, since the root og title is a plain string and so no og template applies.
- **Canonical is relative** (`alternates.canonical: path`), resolved against `metadataBase`, so the preview canonicalises to its own host. Decision: the preview is kept out of search with `X-Robots-Tag: noindex` from `next.config.ts` `headers()` when `isPreviewDeployment()` (`VERCEL_ENV === 'preview'` only). The `*.vercel.app` preview alias got no automatic Vercel noindex (checked with `curl -I`). Not "anything but production": CI's Lighthouse runs `next start` with no `VERCEL_ENV` and scores is-crawlable. A header, not a robots meta, so a 404 still has exactly one meta. It is evaluated at build time, which works because preview and production are separate `vercel build` runs.
- **noindex needs a crawlable page.** `/auth/` and `/share/` carry `robots: NOINDEX` from their layouts and are no longer in robots.txt `Disallow` (a disallowed URL can still be listed from links, without its content). Client-component pages (auth, contact) get metadata from a pass-through `layout.tsx`.
- **404:** Next adds `<meta name="robots" content="noindex">` to every 404 on its own; `metadata.robots` in `app/not-found.tsx` adds a second tag. Leave it out. The same applies to any layout `robots` over a page that calls `notFound()`.
- **JSON-LD:** `serializeJsonLd()` = `JSON.stringify(...).replace(/</g, '\u003c')` (Next's own guide); one `@graph` script (Organization, WebSite, SoftwareApplication). No `aggregateRating`: the ratings stream in after the page (Suspense), and structured data must match the visible figure.
- **Sitemap:** no `lastModified` (build-time `new Date()` on every URL teaches crawlers to ignore it); sitemap and robots take their origin from `getMetadataBase()` (`new URL(path, base).href`).
- **E2E head checks:** compare canonical/og:url by path and to each other, not to a fixed origin (metadataBase depends on the server env); start the dev server with `NEXT_PUBLIC_APP_URL` set to its own port so absolute image URLs can be fetched.
