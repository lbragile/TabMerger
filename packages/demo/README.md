# @tabmerger/demo

Playwright recording and Remotion rendering pipeline for the TabMerger walkthrough and promo videos and the Chrome Web Store listing assets. This is dev tooling and is never shipped.

`demo-script.ts` holds the ordered list of steps, captions and timings. It is the single source of truth for the recording driver (`record.ts`), the screenshot capture (`screenshots.ts`) and the Remotion captions (`remotion/Composition.tsx`). `zoom-origins.json` is committed. `record.ts` measures it and `Composition.tsx` imports it.

## Pipeline

Run from the repo root. Every step uses `pnpm --filter @tabmerger/demo <script>`.

```bash
# 1. Demo-mode extension build (VITE_DEMO_BUILD=true via packages/extension/.env.demo).
#    A regular build dead-code-eliminates Settings > Demo Mode, which the recorder needs.
pnpm --filter @tabmerger/extension build:extension:demo

# 2. Record one .webm per step into public/recordings/<theme>/
pnpm --filter @tabmerger/demo record:dark            # or record:light

# 3. Render into out/
pnpm --filter @tabmerger/demo render:dark            # WalkthroughDemoDark  → out/tabmerger-demo-dark.mp4
pnpm --filter @tabmerger/demo render:light           # WalkthroughDemoLight → out/tabmerger-demo-light.mp4
pnpm --filter @tabmerger/demo render:promo-dark      # also: promo-light, promo-dark-vertical, promo-light-vertical

# Store listing assets
pnpm --filter @tabmerger/demo screenshots            # raw 800×600 PNGs → screenshots/raw/
pnpm --filter @tabmerger/demo store-assets           # 1280×800 screenshots → screenshots/store/, promo tiles → promo/

# Preview compositions interactively
pnpm --filter @tabmerger/demo studio
```

The root `package.json`'s `demo:record`/`demo:render` aliases now run both themes back to back (`record:dark && record:light` / `render:dark && render:light`) — they used to call `record`/`render` scripts that never existed in this package; fixed 2026-09-26.

The recorder launches Chromium **headless by default** (`--headless=new`, `lib/launchDemoContext.ts`) with the unpacked demo build from `packages/extension/.output/chrome-mv3-demo`. It deletes and recreates its profile (`.pw-user-data`) on every run.

**Drag-and-drop steps now work headless too (fixed 2026-09-26).** They used to fail 100% of the time under `--headless=new` — Playwright's `page.mouse.move/down/up` never activated the popup's native `dragstart` in that Chrome mode, even though it dispatches the same underlying CDP `Input.dispatchMouseEvent` call. `lib/actions.ts` now drives every drag (`moveTabToNewWindow`, `crossWindowTabDrag`, `multiSelectTabDrag`, `dragTabToSidebarGroup`, `dragTabBetweenGroups`) through a raw `CDPSession` (`getCdpMouse`/`CdpMouse` in `actions.ts`) instead — the same fix the extension's own real-popup e2e DnD spec (`packages/extension/e2e/rawCdp.ts`'s `RawCdp.drag`) uses, for a different underlying reason. Verified: both themes now record and re-render fully headless with zero relaunch/retry crashes. `TM_DEMO_HEADED=1` still exists as an opt-in for visual debugging, but is no longer required for a normal run.

**Still headed by necessity — `captureClutteredChrome()` in `screenshots.ts`.** This one capture (the promo marquee's "chaos" panel) uses an OS-level `PrintWindow` screen capture to show the real native Chrome tab strip/bookmarks bar (`page.screenshot()`/CDP cannot see native browser chrome at all, headless or not). It launches its own bare, extension-free Chrome window with `headless: false` — unrelated to the DnD fix above, and not portable to headless since there is no real window to `PrintWindow` in that mode. This is the one legitimate exception to "headless by default" in this package.

## Feature tour (drawn browser windows)

A separate 1920x1080/30fps tour of roughly 60-90s that shows browser windows next to TabMerger's popup. Playwright's `recordVideo` cannot capture a browser's own frame and tab strip, so the windows are **drawn in Remotion** (`remotion/tour/BrowserWindow.tsx`: tab strip, toolbar with address bar, page screenshot; props for theme, tab list, per-tab presence and window appear progress so scenes can animate tabs and windows). No real browser window is recorded. The existing compositions, scripts and clips are untouched.

- **One scene per component** in `remotion/tour/scenes/`, listed in `remotion/tour/registry.ts` (id, duration, component). `remotion/tour/TourVideo.tsx` assembles the full tour from the registry with the same hand-rolled cross-fade as `WalkthroughDemo`. Scenes 1 ("the-mess"), 2 ("open-tabmerger"), 3 ("drag-to-new-group"), 4 ("organise-tabs"), 5 ("name-and-note"), 6 ("find-a-tab"), 7 ("restore-group"), 8 ("share-group"), 9 ("sync-devices") and the closing card ("closing-card") are built; a Settings scene was left out (in the recording build Settings is only reachable through the account menu, which shows account details, and the build's settings view includes a development-only tab); later scenes are added by appending a registry entry.
- **Compositions** (`remotion/Root.tsx`): `TourDark` / `TourLight` (full tour) plus `TourScene-<id>-dark|light` for every registry scene.
- **Shared tab data**: `lib/chaosWindows.ts` holds the three windows' URL lists (moved out of `lib/actions.ts`; `chaosHook` imports them, so the real browser windows and the drawn ones can't drift). The real page titles, host and local favicon/screenshot paths for each tab are in `lib/chaosTabs.json`, written by `capture-tour-assets.ts`, which visits every URL headless. Images land in `public/tour/` (gitignored: third-party page content), so on a fresh checkout run the capture once; the render itself needs no network.

```bash
pnpm --filter @tabmerger/demo tour-assets                         # capture titles, favicons, page screenshots (needs network once)
pnpm --filter @tabmerger/demo render:tour-scene the-mess          # one scene -> out/tour/scene-01-the-mess-dark.mp4
pnpm --filter @tabmerger/demo render:tour-scene 1 light           # by number, light theme
pnpm --filter @tabmerger/demo render:tour-scene the-mess --frame=60   # a single still -> out/tour/scene-01-the-mess-dark-f060.png
pnpm --filter @tabmerger/demo render:tour-dark                    # full tour -> out/tour/tabmerger-tour-dark.mp4 (also render:tour-light)
```

- **Scene 2 uses its own popup footage**, not `open-popup`/`chaos-hook`: those shared clips predate the current chaos data (a 4th seed window, 18 tabs, older titles). `record-tour.ts` (`pnpm --filter @tabmerger/demo record:tour [dark|light]`, headless, run once per theme after `build:extension:demo`) opens the same `CHAOS_WINDOW_URLS` windows, clears the setup window, and records `public/tour/recordings/<theme>/tour-open-popup.webm` (800x600, shown 1:1). It never touches `public/recordings/`. It also writes `lib/tourPopupLayout.json` (the three card rects inside the clip and where the settled list starts) and the popup's real tab titles into `lib/chaosTabs.json`, because the popup is the source of truth for what the drawn windows show. Re-run it if the popup layout or the tab list changes.
- **Scene 3 ("drag-to-new-group")** is real, sharp footage recorded by `record-tour-window.ts` (`pnpm --filter @tabmerger/demo record:tour-window [dark|light]`, headless; shared helpers in `lib/tourCapture.ts`). Playwright's `recordVideo` can only record the raw 800x600 viewport, so this grabs 1600x1200 JPEGs via CDP `Page.captureScreenshot` (`clip.scale = 2`), resamples them to 30fps and writes `public/tour/frames/<theme>/window/f-NNNN.jpg` plus `lib/tourWindowFootage.json` (frame counts, event frames, measured timings). The scene pushes in to 1.5x, so it stays crisp. The flow is all real: the first Now Open window card is dragged by its grip onto "Drop for a new group" (`dragWindowToNewGroup` in `lib/actions.ts`), the new "temp group" is renamed "Q4 Launch" (`renameGroup` with `setPace({ renameGroup })`) and coloured pink (`colorNewGroup`), and the popup stays open. Per `docs/drag-and-drop-spec.md` a drop out of Now Open closes every dragged tab at once except the active tab of the window the TabMerger page lives in. So the recorder first moves the popup page into the third real window (where scene 2 opened TabMerger from) and makes the real active tabs match the drawn ones (GitHub, React, Dribbble); the first window then closes completely a fraction of a second after the release. The recorder proves that from the browser (`chrome.windows.get` polling, stored as `windowClosed` and `closeAfterReleaseMs`), and the scene closes drawn window 1 at that measured frame and shows a "Saved and closed" tag where it was. Scene 2's clip is a plain 800x600 video and would benefit from the same capture method.
- **Scene 4 ("organise-tabs")** is saved-group work, so the drawn browser windows fade out in its first 12 frames (scene 3's last frame is rendered under a clip that keeps only the area left of the popup) and never return; `openWindows.ts` still lists them as open. Footage comes from `record-tour-organise-tabs.ts` (`pnpm --filter @tabmerger/demo record:tour-organise-tabs [dark|light]`, headless): it replays scene 3's story unrecorded and quickly (move the popup page into window 3, drag window 1 to a new group, rename "Q4 Launch", colour pink) so the first frame equals scene 3's last frame, then records only scene 4 as 2x CDP frames into `public/tour/frames/<theme>/organise-tabs/` plus `lib/tourOrganiseTabsFootage.json`. Beat A drags Dropbox onto the real "Drop here for a new window" target (Q4 Launch then shows 2 windows). Beat B Ctrl-clicks Google Calendar and Slack (which opens the popup's selection mode: checkboxes and a "2 tabs selected" bar) and drags them together by one grip onto the Work sidebar row (the "+1" ghost rides along; Work gains a new last window, 2 windows and 7 tabs; Q4 Launch ends at 2 windows and 3 tabs), then clicks "Cancel selection". The hold over the Work row is kept short (120ms) because a pointer drag held 600ms over a sidebar row springs that group open and would swap the view away from Q4 Launch. The popup eases to a centred 1.55x. The recorder prints the group states read from the popup DOM at the end. The scene falls back to the dark numbers and frames when light is not recorded; record light with `record:tour-organise-tabs light` when needed.
- **Scene 5 ("name-and-note")** starts on scene 4's last frame (same centred 1.55x popup, no drawn windows, no camera move). `record-tour-name-and-note.ts` (`pnpm --filter @tabmerger/demo record:tour-name-and-note [dark|light]`, headless) replays scenes 3 and 4 unrecorded, checks the pre-roll state in code (header "2 Windows, 3 Tabs", Work 2/7, Q4 Launch 2/3, selection mode off), then records frames into `public/tour/frames/<theme>/name-and-note/` plus `lib/tourNameAndNoteFootage.json`. Beat A double-clicks the second window's title and renames it "Assets" (window rename is its own feature, separate from group and tab rename). Beat B right-clicks the GitHub tab, "Add note", types "Tag the release on Friday" and clicks Save. Tab, window and group notes all show only as a small note icon after saving, and that icon's own tooltip says just "Edit note" (not the text), so hovering it cannot show the saved text. The scene instead draws a sky-blue ring (3 px, a steady base ring plus three expanding "ping" pulses, 1.5s, then fade-out) centred on the saved icon, starting at the measured `noteSaved` frame. The icon centre is measured from the last footage frame's pixels and mapped through the popup position and scale; the last footage frame is held until the ring has finished. The pointer leaves the Save button with a ~50ms flick right at the click, so no row hover or remove button shows. Falls back to dark numbers and frames when light is not recorded.
- **Scene 6 ("find-a-tab")** starts on scene 5's last frame (same centred 1.55x popup, no drawn windows, no camera move, played at the recorded speed). `record-tour-find-a-tab.ts` (`pnpm --filter @tabmerger/demo record:tour-find-a-tab [dark|light]`, headless) replays scenes 3 to 5 unrecorded, verifies that state in code (Q4 Launch 2 windows / 3 tabs with "Assets", Work 2 / 7, one note icon, nothing open), then records frames into `public/tour/frames/<theme>/find-a-tab/` plus `lib/tourFindATabFootage.json`. It clicks the search field, types "slack" (substring match, not fuzzy), and the overlay lists both Slack tabs with a "Work" group badge, which makes the point that search spans all groups. It then clicks the "Find your workspace | Slack" result. In this build selecting a result only switches the popup to that group (no tab highlight, nothing opens in the browser) and clears the query and closes the overlay. Dismissing without selecting (backdrop click) leaves the query text in the header field, which is why the scene picks a result. Once Work has settled (6 frames after the measured overlay-closed frame) a sky-blue (`#0ea5e9`) rounded outline with a very faint fill pulses three times over 1.5s around the found row, then fades; the row rect is measured from the last footage frame's pixels (ink box plus 5 px, `ROW_CSS` in the scene) and mapped through the popup position and scale, and the last footage frame is held until the pulses finish. The scene ends on Work (2 windows, 7 tabs) at scene 5's framing with no highlight.
- **Scene 7 ("restore-group")** starts on scene 6's last frame, eases the popup to the left (1.2x, top-left 40, 70) and draws only the two restored windows on the right (Yahoo Mail + GitHub at 1090, 50; "Assets" with Dropbox at 1130, 500; both at 0.74 of a 1000x580 window). `record-tour-restore-group.ts` (`pnpm --filter @tabmerger/demo record:tour-restore-group [dark|light]`, headless) replays scenes 3 to 6 unrecorded, verifies Work open with Q4 Launch 2/3, then clicks the Q4 Launch row and opens each saved window with its "More window options" menu item "Open in browser". The group-level "Open all in new window" would put every tab in one window, so the per-window action is used. A poller on a second extension page logs, on the grabber clock, when each real window appears (`windowCreated0/1`) and every Now Open badge change; the drawn windows pop in at those frames. Opening leaves the saved group intact (still 2 windows, 3 tabs); Now Open goes 2/10 to 4/13 (with a brief 3/11 to 3/13 flicker while the blank tab of each new window is removed). The recorder prints the real windows before and after.
- **Scene 8 ("share-group")** is the one scene that needs a backend. `record-tour-share-group.ts` (`pnpm --filter @tabmerger/demo record:tour-share-group [dark|light]`, headless) runs against the LOCAL Supabase stack only: Docker Desktop and `pnpm exec supabase start` must be running (the CLI is only available through `pnpm exec supabase`, run from the repo root; no web dev server is needed because the link is only copied, never opened), and the existing `packages/extension/.output/chrome-mv3-demo` build must have been built against the local stack (`.env.local`; do not rebuild it for this). It creates a throwaway Pro user through the local keys from `supabase status -o json` (the same mechanism as `beta-screenshots-sharing.ts`, refusing any non-local URL), replays scenes 3 to 7 unrecorded, signs that user in through the real modal and sets up encryption (all unrecorded), waits for sync and toasts to go quiet, then records: selection mode, tick Q4 Launch, the selection bar Share, and the "Link copied to clipboard" toast, then leaves selection mode and waits for the toast to disappear. The clipboard is captured by overriding `navigator.clipboard.writeText` (extension pages cannot be granted clipboard permission). It proves the share from the backend (one `shared_bundles` row for the user, ciphertext shape only) and deletes the user, which cascades the row. The scene fades the two restored drawn windows out in its first 12 frames and eases the popup back to the centred 1.55x framing. At the cut the only differences from scene 7's last frame are in the header's top-right: the person icon becomes the signed-in avatar (initials "TO") and the undo/redo icons differ slightly. The link itself (`http://localhost:3000/share/<slug>#key=...`) never appears on screen.
- **Scene 9 ("sync-devices")** needs the same local backend as scene 8 (Docker Desktop and `pnpm exec supabase start`, run from the repo root; the existing `chrome-mv3-demo` build built against the local stack; no web dev server). `record-tour-sync-devices.ts` (`pnpm --filter @tabmerger/demo record:tour-sync-devices [dark|light]`, headless, one Node process) creates a throwaway local Pro user, replays scenes 3 to 7 on device A (the demo profile), signs A in and sets up encryption (as in scene 8), then launches device B: a second plain browser profile in a temp directory (not demo mode, so it starts with no groups) with the same extension build, signed in to the same account and unlocked with the passphrase, all unrecorded. B receives the groups at once on sign-in (Q4 Launch with Window and Assets, the GitHub note icon, colours and counts; its Now Open differs because it has its own real windows). Both popups are recorded by two frame grabbers on one clock into `public/tour/frames/<theme>/sync-devices/a` and `/b`, with B's offset stored in `lib/tourSyncDevicesFootage.json`. A live change on A did reach B without any action on B (a probe starred a group: 9 s), but that is paced by A's 30 s sync poll in the popup, so it is not a holdable beat; the scene therefore shows B already having everything. The recorder proves from the backend that the synced rows exist with ciphertext content (shape only: every `windows` value is a `{v,iv,ct}` object, and no known group or tab name appears in the rows) and deletes the user and the temp profile. The scene starts on scene 8's last frame, eases A smaller to the left (1.08x at 60, 110), brings B in on the right (996, 110) and shows two small plain labels ("This computer", "Your other computer"). Nothing is clicked.
- **Closing card ("closing-card")** is the tour's last scene (the 10th in the registry) and is pure Remotion, no footage and nothing to record. It starts on scene 9's last frame (rendered in a negative-`from` Sequence that fades and gently scales away over 15 frames), then the logo (`public/logo.png`, shown 1:1), the name "TabMerger", the tagline "Tab chaos, tamed." and "Free to start" with the site address ease in with a short stagger and hold (4.0s). Wording comes from existing material: the tagline and "Free to start" from the walkthrough outro in `demo-script.ts`, the address as spelled in `packages/extension/CHROMEWEBSTORE.md` (the production site); the promo outro says "TabMerger, install free" and the site hero says "Stop drowning in browser tabs." if a different line is preferred. It is theme-aware (`THEME_COLORS`). A scene whose registry caption is empty draws no caption bar: the full tour fades the bar out over that scene's first 10 frames, and the single-scene composition draws none.
- **Tour thumbnail (poster image)** is a still, separate from the video (the video has no entry card): `remotion/tour/TourThumbnail.tsx`, compositions `TourThumbnail-dark` / `TourThumbnail-light` (1920x1080). Render with `pnpm --filter @tabmerger/demo render:tour-thumbnail [dark|light]` -> `out/tour/tabmerger-tour-thumbnail-dark.png` and `...-dark-1280.png` (Remotion `--scale`, same layout). It is the frame people see before pressing play: logo, "TabMerger" and the site hero headline "Stop drowning in browser tabs." on the left, and on the right an enlarged (1.8x), cropped view of the real popup (the last footage frame of scene 7, signed out, Q4 Launch selected): the header's logo and name, the whole sidebar group list and the two window cards, bleeding off the right edge on purpose. Text and product stay clear of the centre band and the bottom of the frame that players cover. No caption bar, play button, web address or badges.
- **Light theme and the full tour.** Every tour scene now has dark and light footage (`record:tour-* light` writes `public/tour/frames/light/<scene>/` and the `light` entries of `lib/tour*Footage.json` without touching `dark`). Scene durations and caption cues are theme independent and equal the dark values (135, 195, 321, 254, 226, 183, 205, 203, 120, 120 frames): durations come from the dark footage and caption cues from the dark event frames, so light footage that runs longer only loses idle end frames, and per-theme overlay timings (the note-icon ring, the found-row highlight, the drawn restored windows) use each theme's own events. The overlay positions were re-measured on the light frames and are identical to dark, so they share one constant. Re-record notes: scenes 8 and 9 need Docker and `pnpm exec supabase start` (local stack only, throwaway user created and deleted by the recorder); scenes 4 to 7 need no backend; every recorder replays the earlier scenes unrecorded and verifies the state in code.
- **Full tour, intro and audio.** `pnpm --filter @tabmerger/demo render:tour-dark` / `render:tour-light` render `out/tour/tabmerger-tour-<theme>.mp4` (1920x1080, 30 fps, 2072 frames = 69.07 s, h264 + AAC). The video opens with the poster image: `TourThumbnail` (the same component the standalone `render:tour-thumbnail` PNG uses, so frame 0 of the video is pixel-identical to `tabmerger-tour-<theme>.png`... see the thumbnail note) fully opaque from frame 0, held for 30 frames, then dissolving into scene 1 (`TOUR_INTRO_HOLD_FRAMES` in `remotion/tour/registry.ts`); the caption bar is absent during the intro and fades in with scene 1. Every scene after the first holds its first frame while it fades in (8 frames) and the outgoing scene stays opaque underneath, so a cut between frame-matched scenes is a clean dissolve with no dip or double image; the tour length is the intro hold plus the scene durations plus 8 frames per scene (`getTourDurationInFrames`). A scene with an empty registry caption (the closing card) draws no caption bar.
- **Sound design (optional, synthesised).** `pnpm --filter @tabmerger/demo audio:tour [dark|light]` runs `generate-tour-audio.ts`, which writes `public/tour/audio/tour-<theme>.wav` (gitignored) and `out/tour/audio/tour-audio-<theme>.json`. It is sound effects only: no music bed, no transition sounds (nothing is tied to a scene cut: no whoosh, no swell) and no third-party audio, so there is nothing to license or credit. It is procedural (sine based, low-pass filtered, no samples), deterministic, in D major, and timed from the real data: scene cut frames from the registry and event frames from `lib/tour*Footage.json` mapped through each scene's START and FOOTAGE_SPEED. The sounds are a rising pentatonic stack under the poster intro, a short tick, pluck, thump or chime on each real event (drops, clicks, typing ends, restores, the copied link; plus one soft tone swell when the second device arrives in the sync scene) and a strummed chord on the closing card; between them the tour is silent, and it fades to exact silence at the last frame. The mix gets a fixed gain (`SFX_GAIN_DB`, 7.5 dB) and ffmpeg's `alimiter` (limit 0.8), not a normalisation to a target LUFS, so adding or removing a sound never changes the level of the others; the result measures about -19.7 LUFS integrated, -1.9 dBTP true peak and 24 LU loudness range (long silences between sounds) (the closing chord is the only sound that reaches the limiter, by about 1 dB). Loudness is measured with ffmpeg's `ebur128`; the ffmpeg bundled with Remotion has no such filter, so set `TM_FFMPEG` to a full ffmpeg build. `pnpm --filter @tabmerger/demo audio:chart` draws `out/tour/audio/tour-audio-<theme>-chart.png` (envelope, spectrogram, cuts and event markers) to check the sync by eye. `TourVideo` plays the WAV through one Remotion `<Audio>` for the whole tour, only if the file exists and the prop `audio` is not false (the `render:tour-*-silent` scripts in `package.json` pass `audio: false`). Nothing depends on sound: the tour is complete muted. There is no `public/audio/track.mp3` and the tour does not use it.
- **Open windows per scene** live in `remotion/tour/openWindows.ts` (which drawn windows are open when each scene ends); scenes read `openWindowsBefore/After(sceneId)` so a closed window cannot reappear by accident. Windows restored from a saved group (scene 7) are tracked separately there (`restoredWindowsAfter`), so the three-window tuple stays the source of truth for the originals.
- **Timed captions**: a scene's registry `caption` is a string or a list of `{from, text}` cues (scene-local frames); the tour layer draws them and blanks the text for 6 frames around each change.
- Captions are drawn once at the tour level (`TourVideo.tsx`, text from the registry's `caption`), blank for a few frames around each cut so two captions never overlap; scenes draw no caption themselves. Every drawn window carries the pinned TabMerger toolbar icon in every scene, so it never pops in during a cross-fade.
- The window-to-card link in scene 2 is colour + number + connector line per pair (`PAIR_COLORS`, `POPUP` and `SETTLED` in `Scene02OpenTabMerger.tsx`; card positions from `lib/tourPopup.ts`).

One tab (Super User) has no usable headless page capture (bot-wall HTML), so it shows a blank page with its favicon and is never the active tab in a scene. The third window's LinkedIn and X tabs were swapped for Dribbble and Flickr (2026-10-08) because the extension recorder got a Cloudflare wall and an empty title for them; see the comment in `lib/chaosWindows.ts`.

## Outputs

`recordings/`, `out/`, `screenshots/` and `promo/` are all gitignored (`packages/demo/.gitignore`). Nothing copies them into the web app automatically. After a render that should ship on the marketing site, run the user-invoked `/demo-asset-sync` skill. It re-encodes `out/tour/tabmerger-tour-{dark,light}.mp4` to 1280x720 in `packages/web/public/videos/` together with a first-frame poster for each theme, and only those files are committed.

## Audio

The video is instrumental only, with no voiceover or TTS step. You can drop a background track at `public/audio/track.mp3`. If that file is absent, the render leaves out the `<Audio>` element. The file is not gitignored (only `public/audio/.gitkeep` is committed), so don't commit a licensed track by accident.

See `PROMO_VIDEO_SPEC.md` for the promo-cut plan.
