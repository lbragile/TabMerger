<QuickAnswer>

<Kbd>Ctrl</Kbd>+<Kbd>Tab</Kbd> and <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>Tab</Kbd> switch to the next and previous tab, <Kbd>Ctrl</Kbd>+<Kbd>1</Kbd>…<Kbd>8</Kbd> jump to a tab by position, <Kbd>Ctrl</Kbd>+<Kbd>W</Kbd> closes it and <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>T</Kbd> brings it back. These work the same in Chrome, Edge and Firefox on Windows and Linux; on a Mac, use <Kbd>⌘</Kbd> instead of <Kbd>Ctrl</Kbd>. Add [TabMerger](/features) and two more keys do the heavy lifting: save tabs straight from the keyboard, and <Kbd>Ctrl</Kbd>+<Kbd>K</Kbd> to find any tab, open, saved or closed.

</QuickAnswer>

<Section id="reopen" title="How do I reopen a tab I closed by mistake?">

Press <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>T</Kbd> (<Kbd>⌘</Kbd>+<Kbd>Shift</Kbd>+<Kbd>T</Kbd> on a Mac). Each press goes one step further back. What “back” includes depends on the browser:

<BrowserPanels section="reopen">
<BrowserPanel browser="chrome">

Chrome reopens tabs *and* windows, in the order they were closed, so keep pressing until the window you lost is back.

</BrowserPanel>
<BrowserPanel browser="edge">

Edge documents <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>T</Kbd> as reopening the last closed tab. For a closed window, open History (<Kbd>Ctrl</Kbd>+<Kbd>H</Kbd>) and look under **Recently closed**.

</BrowserPanel>
<BrowserPanel browser="firefox">

Firefox keeps separate lists: <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>T</Kbd> for tabs and <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>N</Kbd> for windows. In Firefox 159 <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>T</Kbd> is wired to a command named “restore last closed tab, window or session”, so it can also bring back the previous session.

</BrowserPanel>
</BrowserPanels>

The list only goes back so far. For a whole lost session, see [how to restore tabs after a crash](/blog/restore-tabs-after-crash). To stop losing them in the first place, [save all your open tabs](/blog/save-all-open-tabs) before you close anything big.

</Section>

<Section id="extensions" title="How do I set shortcuts for extensions?">

Extensions can suggest shortcuts, but the browser has the final say: a suggested key that clashes with one of the browser’s own is left **Not set**, without a warning. Open your browser’s shortcuts page, click the pencil next to a command and press the keys you want.

<BrowserPanels section="extensions">
<BrowserPanel browser="chrome">

Paste `chrome://extensions/shortcuts` into the address bar. Each command also has a scope menu: **In Chrome**, or **Global** to make it work when Chrome isn’t focused.

</BrowserPanel>
<BrowserPanel browser="edge">

Paste `edge://extensions/shortcuts` into the address bar.

Edge keeps <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>K</Kbd> (duplicate tab), <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>U</Kbd> (Read Aloud) and <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>P</Kbd> (print with the system dialog) for itself, so an extension command that suggests one of them starts as **Not set** in Edge 158. Edge 158 also refuses some <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd> keys that Microsoft’s list doesn’t mention, such as <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>A</Kbd> and <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>Z</Kbd>. TabMerger’s save commands avoid all of them, so a new install has all four set:

</BrowserPanel>
<BrowserPanel browser="firefox">

Open `about:addons`, click the gear menu and choose **Manage Extension Shortcuts**. Note that <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>P</Kbd> opens a private window in Firefox, so pick another key for anything that suggests it.

</BrowserPanel>
</BrowserPanels>
