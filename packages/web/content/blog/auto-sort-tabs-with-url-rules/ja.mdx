<QuickAnswer>

[TabMerger](/features) で **設定 → 一般 → URLルール → 管理**（Settings → General → URL rules → Manage）を開き、ルールを追加します。ルールは `github.com/your-org/*` のようなアドレスのパターンと、振り分け先のグループです。以降はブラウジング中に一致したページがすべてそのグループに保存され、タブは開いたままです。`*` は何にでも一致し、最初に一致したルールが適用されます。

</QuickAnswer>

<InstallCta>タブがひとりでに正しいグループへ。Chrome、Edge、Firefox で無料。</InstallCta>

<Section id="problem" title="手作業でのタブ整理は続かない">

週の始まりはきちんと整っています。仕事はひとつのグループ、旅行は別のグループ、読み物は3つ目のグループ。ところが一日が始まると、同僚から Issue のリンクが届き、電車の時刻を2本調べ、検索で記事が見つかります。どれもどこかに入れるべきものですが、そのたびにドラッグするのは面倒で、結局やりません。金曜日にはグループが古くなり、現在開いているタブ（Now Open）はまた山積みです。

よく開くページは、決まったいくつかのサイトから来ています。それこそがルールで見分けられるものです。

</Section>

<Section id="why" title="URLルールがこう動く理由">

- **移動ではなくコピー**。ルールはページのコピーをグループに保存し、タブは開いたままにします。読んでいる最中に整理で邪魔されることはありません。
- **ブラウジング中に見張る**。ルールは、タブがアドレス付きで開いたときと、ページの読み込みが終わるたびに確認されます。そのため、タブ内でたどったリンクも振り分けられます。コピーはグループの最初のウィンドウに入ります。同じページが再び読み込まれると（再読み込みや後日の訪問）もう一度保存されますが、グループの **⋯** メニューにある **重複タブを削除**（Deduplicate tabs）で重複を片付けられます。
- **スキームを除いたアドレス全体**。パターンは `http://` や `https://` の後ろにあるアドレス全体と比べられるので、それらを入力する必要はなく、`localhost:3000/*` も書いたとおりに動きます。
- **ワイルドカードはあえてひとつ**。`*` は空も含めた任意の文字列を意味します。エスケープが必要な特殊文字はほかにありません。パターンはプレーンテキストとして照合され、正規表現に変換されることはないので、長いパターンでもすばやく確認されます。
- **順序で決まる**。2つのルールが一致したら上のほうが適用されるので、具体的なルールを一般的なルールの上に置けます。

</Section>

<Section id="steps" title="ルールを追加する">

1. TabMerger を開き、**設定** → **一般**（Settings → General）に進みます。**URLルール** の横にある **管理**（Manage）を押します。
2. **ルールを追加**（Add rule）を押します。パターンを入力し、振り分け先のグループを選んで、ダイアログの **ルールを追加** を押します。
3. 振り分けたいサイトごとに繰り返し、最後に **保存**（Save）を押してリストを保存します。

<Section id="patterns" title="一致するパターンの書き方">

<ComparisonTable
  head={['パターン', '一致するもの', '一致しないもの']}

  rows={[

    ['localhost:3000/*', 'ローカル開発サーバーのすべてのページ', 'localhost:8080/…'],
    ['docs.example.com/*', 'ドキュメントサイト', 'www.docs.example.com/…（*docs.example.com/* を追加）'],
    ['github.com', 'github.com というアドレスそのものだけ', 'github.com/anything（/* を追加）'],
  ]}
/>

デバッグの手間を省くコツ：

- **末尾を `/*` にする**と、サイト全体が対象になります。`*` がないと、パターンはひとつのアドレスにだけ完全一致します。
- **先頭を `*` にする**のは、サイトがサブドメインや `www.` を使う場合です（例：`*example.com/*`）。
- **文字は書いたとおりに一致させる**。ブラウザはドメイン名を小文字で書くので、パターンも小文字で書きましょう。
- **クエリ文字列も対象**。`*youtube.com/watch*` は、`watch` の後に何が続いても動画に一致します。

</Section>

<Section id="order" title="ルールの順序：具体的なものを先に">

ルールは上から試されます。各ルールの横の矢印を使って、範囲の狭いルール（`github.com/your-org/design-system/*` → 「Design system」）を広いルール（`github.com/your-org/*` → 「Work」）より上に置きましょう。最初に一致したルールがページを振り分け、残りは飛ばされます。

</Section>

<Section id="benefit" title="得られること">

自分で整理しなくても、グループは常に最新の状態です。火曜日に開いたページは金曜日にはもうプロジェクトのグループに入っていて、そのグループを検索すれば見つかります。

</Section>

<Section id="habits" title="よい習慣">

- **毎日開くサイトにルールを作る**。一度しか訪れないサイトにまでは不要です。
- **プロジェクトのドメインやパスごとにルールをひとつ**、具体的なルールを先に。
- **ルールとプロジェクトごとのグループを組み合わせる**：[プロジェクトごとにタブを整理する](/blog/organize-tabs-by-project)をご覧ください。開発者向けのパターンは[開発者のためのタブ管理](/blog/tab-management-for-developers)にもっとあります。
- **ときどき片付ける**。ルールでよく埋まるグループでは **重複タブを削除** を使いましょう。

</Section>
