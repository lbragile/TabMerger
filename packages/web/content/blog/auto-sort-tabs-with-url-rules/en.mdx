<QuickAnswer>

In [TabMerger](/features), open **Settings → General → URL rules → Manage** and add a rule: an address pattern such as `github.com/your-org/*` and the group it belongs to. From then on, every page that matches is saved into that group as you browse, and the tab stays open. `*` matches anything; the first matching rule wins.

</QuickAnswer>

<InstallCta>Tabs that file themselves into the right group. Free for Chrome, Edge and Firefox.</InstallCta>

<Section id="problem" title="Filing tabs by hand doesn’t last">

You start the week organised: work in one group, the trip in another, reading in a third. Then the day happens. A colleague links an issue, you look up two train times, a search turns up an article. Each one should go somewhere, and each one is a drag you won’t do. By Friday the groups are out of date and Now Open is a pile again.

The pages you open most often come from the same few sites. That is exactly what a rule can recognise.

</Section>

<Section id="why" title="Why URL rules work the way they do">

- **Copy, don’t move.** A rule saves a copy of the page into the group and leaves the tab open. Filing never interrupts what you’re reading.
- **Watches as you browse.** A rule is checked when a tab opens with an address and whenever a page finishes loading, so a link you follow inside a tab is filed too. The copy goes into the group’s first window. A page that loads again (a reload, a later visit) is saved again; **Deduplicate tabs** in the group’s **⋯** menu clears repeats.
- **The whole address, no scheme.** A pattern is compared with the entire address after `http://` or `https://`, so you never type those, and `localhost:3000/*` works as written.
- **One wildcard, on purpose.** `*` means any run of characters, including none. There are no other special characters to escape. Patterns are matched as plain text, never turned into a regular expression, so even long patterns are checked quickly.
- **Order decides.** When two rules match, the higher one wins, so a specific rule can sit above a general one.

</Section>

<Section id="steps" title="Add a rule">

1. Open TabMerger, then **Settings** → **General**. Next to **URL rules**, press **Manage**.
2. Press **Add rule**. Type the pattern, choose the target group, and press **Add rule** in the dialog.
3. Repeat for each site you want filed, then press **Save** to keep the list.

Tips that save a debugging session:

- **End with `/*`** to cover a whole site. Without a `*`, a pattern matches one exact address.
- **Start with `*`** when a site uses subdomains or `www.`: `*example.com/*`.
- **Letters must match as written.** Browsers write domain names in lowercase, so write them that way too.
- **Query strings count.** `*youtube.com/watch*` matches videos whatever comes after `watch`.

</Section>

<Section id="order" title="Rule order: specific first">

Rules are tried from the top. Put the narrow rule (`github.com/your-org/design-system/*` → “Design system”) above the broad one (`github.com/your-org/*` → “Work”), using the arrows next to each rule. The first rule that matches files the page, and the rest are skipped.

</Section>

<Section id="benefit" title="What you get">

Your groups stay current without any filing on your part. A page you opened on Tuesday is already in its project’s group on Friday, and searching that group finds it.

</Section>

<Section id="habits" title="Good habits">

- **Rule the sites you open daily,** not every site you visit once.
- **One rule per project domain or path**, specific rules first.
- **Pair rules with groups per project:** see [organize tabs by project](/blog/organize-tabs-by-project). Developers will find more patterns in [tab management for developers](/blog/tab-management-for-developers).
- **Tidy now and then** with **Deduplicate tabs** on groups that rules fill often.

</Section>
