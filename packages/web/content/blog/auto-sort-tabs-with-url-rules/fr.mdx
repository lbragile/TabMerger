<QuickAnswer>

Dans [TabMerger](/features), ouvrez **Paramètres → Général → Règles d’URL → Gérer** (Settings → General → URL rules → Manage) et ajoutez une règle : un modèle d’adresse comme `github.com/your-org/*` et le groupe auquel il appartient. Dès lors, chaque page correspondante est enregistrée dans ce groupe pendant que vous naviguez, et l’onglet reste ouvert. `*` correspond à tout ; la première règle qui correspond l’emporte.

</QuickAnswer>

<InstallCta>Des onglets qui se rangent tout seuls dans le bon groupe. Gratuit pour Chrome, Edge et Firefox.</InstallCta>

<Section id="problem" title="Ranger ses onglets à la main ne tient pas">

Vous commencez la semaine bien organisé : le travail dans un groupe, le voyage dans un autre, la lecture dans un troisième. Puis la journée suit son cours. Un collègue partage le lien d’un ticket, vous cherchez deux horaires de train, une recherche fait remonter un article. Chacun devrait aller quelque part, et chacun est un glisser-déposer que vous ne ferez pas. Le vendredi, les groupes sont dépassés et Ouverts maintenant (Now Open) est redevenu un fouillis.

Les pages que vous ouvrez le plus souvent viennent des mêmes quelques sites. C’est exactement ce qu’une règle sait reconnaître.

</Section>

<Section id="why" title="Pourquoi les règles d’URL fonctionnent ainsi">

- **Copier, pas déplacer.** Une règle enregistre une copie de la page dans le groupe et laisse l’onglet ouvert. Le rangement n’interrompt jamais votre lecture.
- **Surveille pendant que vous naviguez.** Une règle est vérifiée quand un onglet s’ouvre avec une adresse et chaque fois qu’une page termine de charger : un lien suivi à l’intérieur d’un onglet est donc rangé lui aussi. La copie va dans la première fenêtre du groupe. Une page qui se recharge (actualisation, visite ultérieure) est enregistrée de nouveau ; **Dédupliquer les onglets** (Deduplicate tabs), dans le menu **⋯** du groupe, supprime les doublons.
- **L’adresse entière, sans schéma.** Un modèle est comparé à toute l’adresse qui suit `http://` ou `https://` : vous ne les tapez jamais, et `localhost:3000/*` fonctionne tel quel.
- **Un seul joker, volontairement.** `*` désigne n’importe quelle suite de caractères, y compris aucune. Il n’y a aucun autre caractère spécial à échapper. Les modèles sont comparés en texte brut, jamais transformés en expression régulière, si bien que même les modèles longs sont vérifiés rapidement.
- **L’ordre décide.** Quand deux règles correspondent, celle du haut l’emporte : une règle précise peut donc se placer au-dessus d’une règle générale.

</Section>

<Section id="steps" title="Ajouter une règle">

1. Ouvrez TabMerger, puis **Paramètres** → **Général** (Settings → General). À côté de **Règles d’URL**, cliquez sur **Gérer** (Manage).
2. Cliquez sur **Ajouter une règle** (Add rule). Saisissez le modèle, choisissez le groupe cible, puis cliquez sur **Ajouter une règle** dans la boîte de dialogue.
3. Recommencez pour chaque site à ranger, puis cliquez sur **Enregistrer** (Save) pour conserver la liste.

Des astuces qui vous épargnent une séance de débogage :

- **Terminez par `/*`** pour couvrir un site entier. Sans `*`, un modèle correspond à une seule adresse exacte.
- **Commencez par `*`** quand un site utilise des sous-domaines ou `www.` : `*example.com/*`.
- **Les lettres doivent correspondre telles quelles.** Les navigateurs écrivent les noms de domaine en minuscules ; faites de même.
- **Les paramètres de requête comptent.** `*youtube.com/watch*` correspond aux vidéos, quoi qu’il y ait après `watch`.

</Section>

<Section id="order" title="Ordre des règles : le précis d’abord">

Les règles sont essayées à partir du haut. Placez la règle étroite (`github.com/your-org/design-system/*` → « Design system ») au-dessus de la règle large (`github.com/your-org/*` → « Work ») avec les flèches à côté de chaque règle. La première règle qui correspond range la page, et les autres sont ignorées.

</Section>

<Section id="benefit" title="Ce que vous y gagnez">

Vos groupes restent à jour sans aucun rangement de votre part. Une page ouverte le mardi est déjà dans le groupe de son projet le vendredi, et une recherche dans ce groupe la retrouve.

</Section>

<Section id="habits" title="Bonnes habitudes">

- **Créez des règles pour les sites que vous ouvrez chaque jour,** pas pour chaque site visité une fois.
- **Une règle par domaine ou chemin de projet**, les règles précises en premier.
- **Associez les règles à un groupe par projet :** voir [organiser ses onglets par projet](/blog/organize-tabs-by-project). Les développeurs trouveront d’autres modèles dans [la gestion des onglets pour les développeurs](/blog/tab-management-for-developers).
- **Faites le ménage de temps en temps** avec **Dédupliquer les onglets** dans les groupes que les règles remplissent souvent.

</Section>
