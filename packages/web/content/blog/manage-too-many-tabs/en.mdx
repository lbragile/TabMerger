<QuickAnswer>

Run four steps, in this order: **close** every tab you’ve finished with, **group** the tabs for the task in front of you, **save** the “maybe later” tabs somewhere you can search, and **schedule** a ten-minute sweep once a week. It works in Chrome, Edge and Firefox. The step that clears the most is saving, and [TabMerger](/features) makes it one click: every open window saved into a named group you can search and reopen any time.

</QuickAnswer>

<Section id="how-many" title="How many tabs is too many?">

There’s no magic number, and we won’t invent one. Tabs become a problem when they stop doing their job, which is holding things you’ll come back to soon. Watch for these signs:

- The tab strip shows icons only, so you can’t read titles any more.
- You open a page and find it was already open, twice.
- You keep tabs open “just in case”, because closing them feels like losing them.
- The browser warns you. Chrome shows **Performance issue alerts** that suggest deactivating tabs when it detects poor performance.

The last one is the browser’s problem, and it has fixes (below). The first three are a filing problem, and that’s what the routine fixes.

</Section>

<Section id="close" title="1. Close what you’ve finished with">

Start with the cheapest win. Close tabs whose job is done: the search you already answered, the article you already read, the checkout page.

- <Kbd>Ctrl</Kbd>+<Kbd>W</Kbd> (<Kbd>⌘</Kbd>+<Kbd>W</Kbd> on a Mac) closes the current tab in all three browsers.
- Closed one too many? <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>T</Kbd> reopens it. More in our [tab keyboard shortcuts](/blog/tab-keyboard-shortcuts) reference.

<BrowserPanels section="close">
<BrowserPanel browser="chrome">

Press <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>A</Kbd> (<Kbd>⌘</Kbd>+<Kbd>Shift</Kbd>+<Kbd>A</Kbd> on a Mac) to open **Tab Search**: a list of every open tab, with a close button on each row. Close the ones you’re done with straight from the list.

</BrowserPanel>
<BrowserPanel browser="edge">

Edge’s keyboard shortcut list has no key for searching open tabs, so work along the tab strip: click a tab you’re done with and press <Kbd>Ctrl</Kbd>+<Kbd>W</Kbd>.

</BrowserPanel>
<BrowserPanel browser="firefox">

- <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>A</Kbd> lists all your tabs, so you can find and close the ones you’re done with.
- Right-click any tab and choose **Close Duplicate Tabs** to clear repeats in one go.

TabMerger clears repeats across **every** window at once; see [how to close duplicate tabs](/blog/close-duplicate-tabs).

</BrowserPanel>
</BrowserPanels>

<Catch>closing is only safe for tabs you’re sure about. Anything you hesitate over goes to step 3, not to the bin.</Catch>

</Section>

<Section id="group" title="2. Group the tabs for today’s task">

Tab groups give a set of tabs a name and a colour, and collapse them to a single label. Chrome, Edge and Firefox all have them: right-click a tab and add it to a new group.

Keep one group per task you’re actually working on today, and collapse the ones you aren’t looking at. A collapsed group takes the space of one tab. How groups save, sync and reopen differs by browser; our [guide to Chrome tab groups](/blog/chrome-tab-groups) covers the details and the limits.

</Section>

<Section id="save" title="3. Save the “maybe later” tabs">

This is the step that actually shrinks the tab strip. A tab you might need next week doesn’t need to be open; it needs to be findable.

- **Bookmark the window.** <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>D</Kbd> saves every tab in the current window into a new bookmark folder. Our guide to [saving all open tabs](/blog/save-all-open-tabs) walks through it per browser.
- **Use a session manager.** It saves whole windows, with names, and restores them in one click. See [what a browser session manager does](/blog/browser-session-manager) and how it differs from bookmarks.
- **Read later.** If it’s an article, a read-later list beats a tab. Not sure which home a page needs? Our [tabs vs bookmarks guide](/blog/tabs-vs-bookmarks) has a decision table.

Then close what you saved. That’s the whole trick: saving is what makes closing safe.

</Section>

<Section id="schedule" title="4. Put a weekly sweep on the calendar">

Tabs creep back. A short, regular sweep keeps the count down without willpower:

1. Once a week, open your saved folders or groups.
2. Delete what you no longer need. If you haven’t opened it in a month, you probably won’t.
3. Close the windows you saved during the week.

If you research for a living (students, analysts, developers reading docs), keep one saved group per project and sweep it when the project ends, not before.

</Section>

<Section id="memory" title="Let the browser free the memory">

Browsers can stop idle tabs using memory without closing them. The tab stays in the strip and reloads when you click it.
